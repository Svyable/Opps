## Why this one rather than another new application

This is distinct from (1) EA Funds' proposed blinded *human claim-verification experiment* and (2) Foresight's proposed *authorization-gate comparison*. **Suggested short application thesis, for applicant editing (not a verified field):**

> AI agents can claim they obtained approval or completed a tool action when the independent evidence is incomplete or contradictory. We propose an open-source, fail-closed receipt SDK that binds an observed tool result to its arguments, authorization and provenance, and explicitly abstains when those observations are absent. Existing Svyable code provides testable prototypes, not deployment evidence. Over six months we would integrate one permitted framework, invite independent reproduction, and publish both failures and a stop/continue decision.

**Deliverables that can actually be assessed:** one documented isolated tool integration; a public versioned threat model; reproducible integrity, replay, scope and missingness tests; installation guide; independently reproduced or explicitly *not* reproduced results; external-adopter count reported even if zero; and a transparent go/no-go decision. No unearned adoption, performance or safety-efficacy claim.

4. **IP and distribution:** applicant checks actual repository licenses, contributor permissions, contractor IP, framework license and public release rights. Do not promise a license not already cleared.
5. **Credibility:** public code and CI support feasibility only. No third-party telemetry, independent security certification, customer deployment, reference consent or personnel commitment exists in the verified record.

## Concrete implementation and local test
Existing [funding_overlap.py](../artifacts/control-evidence-2026/funding_overlap.py) keys uniqueness on (package, date, contributor, deliverable). Therefore the *same scope* allocated to two funders on different dates or with different contributor text can evade its duplicate check. Added [funding_release_gate.py](../artifacts/control-evidence-2026/funding_release_gate.py), a separate strict preflight keyed on stable **scope_id** independent of dates, descriptions and contributors, rejecting empty schedules, missing scope IDs, nonfinite or invalid amounts/hours and unknown funders. It does **not** replace the existing checker or claim to infer semantic equivalence. A malicious or mistaken re-labeling of the same work with two different IDs still passes; a human must reconcile actual deliverables and signed sponsor scopes.

[10 new regression tests](../artifacts/control-evidence-2026/test_funding_release_gate.py) passed locally using Python unittest on 2026-11-09 (10/10; 0 failures). No remote CI result claimed. The four planned BlueDot scopes BD-R3-THREAT, BD-R3-FIXTURE, BD-R3-NEGATIVE, BD-R3-GATE must remain excluded from any EA-funded schedule. This tool is a planning gate, **not** a sponsor-approved budget, proof of actual hours, or an authorization to submit.
